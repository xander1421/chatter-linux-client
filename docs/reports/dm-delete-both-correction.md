# DM delete-for-both correction

This followup corrects a2d244ba on both friend and anonymous 1:1 receive paths. The friend-DM processor now emits the deleted stored message's actual author instead of the authenticated control sender. Friend-DM target selection admits only ServerDm rows in the authenticated peer's conversation and only peer/current-user authors. Own-device sync retains its existing cross-DM semantics but explicitly refuses other conversation types.

ConversationHandle's shared standard DM/channel lookup now uses conversation type + ID + author + timestamp; menu, ownership, attachment and other operations that use that lookup cannot reach unrelated rows. Sending deletion captures that scoped target before dispatch, then uses its ID for local/server cleanup. Sender-side DM deletion records a typed tombstone too. Channel inbound deletion explicitly requires Channel rows and the supplied conversation ID; group handling stays author-only.

The legacy deletion wire specifies a target timestamp without target author. Missing incoming DM targets therefore queue tombstones for both possible participant authors within the exact DM. Existing pending modifier `body` carries `server_dm` or `anon_dm`, and the existing emoji uniqueness component namespaces type/conversation to avoid overwriting another scoped tombstone. No migration is added. Arrival checks require the matching type and preserve typed tombstones through deleted arrivals and unrelated-type arrivals, so repeated catchup cannot resurrect them. Existing 30-day / 1000-item pruning is unchanged. Timestamp collisions between the two participants remain inherently ambiguous in this existing wire protocol; the existing peer-first selection is retained within the strict DM scope.

The friend-DM receive wrapper captures our sealed-message deletion token before removing its source row and starts a best-effort server deletion with the captured capability. Domain emission does not wait for networking. No token is logged. Server cleanup failure is logged and does not undo local deletion; the existing bounded tombstone retention still applies, so persistent remote failure beyond that retention remains an operational limitation.

Anonymous DM `process_incoming_content` handles deletion before the common group dispatcher: it validates the active conversation, authenticated peer and block state, resolves either participant's scoped AnonDm message, and emits its actual message ID/author. Missing targets use typed AnonDm tombstones. The common group dispatcher is unchanged. Anonymous catchup processing filters reconstructed MessageReceived events whose rows were suppressed by pending deletion, preventing live ghost bubbles. Anonymous DM sender-keyed lookup and local timestamp deletion are now type-scoped.

`latest_message` searches at most eight pages of 32 rows, skipping only typed `SystemMessage::DisappearingTimerChanged` notices. It preserves other system events and returns None if only notices remain inside the bounded search. Paging uses the existing strictly decreasing sent_at cursor and a progress guard.
