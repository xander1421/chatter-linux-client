Exact-author delete protocol correction

Contract
- Delete.target_author_aci is optional string extension field 101; Delete.destination_user_id is optional string extension field 102, solely for authenticated self-device ServerDm copies. Go stores *string; Rust stores Option<String>. Absence and explicit empty are distinct.
- ConversationHandle::send_delete routes exact target_author through build_targeted_delete_content(timestamp, Some(author), optional_channel). Anonymous DM and group production senders also set Some(author); timestamp-only public builder wrappers remain legacy compatibility.
- Standard DM: authenticated sender establishes ServerDm conversation. Present author must parse as current user or sender; absent author means sender only. Exact conversation/type lookup removes only that row; missing targets queue only that admitted author with ServerDm scope. Other-scope rows remain untouched but do not prevent a typed in-scope tombstone. Self-device sender must supply a valid non-self destination and explicit author (us or destination); missing legacy self destination/author is refused without guessing. Peer-delivered controls reject any destination claim.
- Anonymous DM: active, unblocked conversation must authenticate sender as its peer. Same optional-author admission applies; exact AnonDm scope/type, one-author tombstone, and legacy peer-only fallback. Inner channel and self-device destination claims are refused.
- Channel and anonymous group controls reject a present author different from authenticated sender, including malformed/empty values, before applying a sender-only mutation. Group precheck and SQL mutation both require exact AnonGroup type. Channel and group controls also reject self-device destination claims.
- Explicit empty author is rejected; it never falls back to legacy. No cross-author guessing remains.
- Previous receivers ignore field 101: their timestamp-only selection is peer-first, and a missing target queues both participant authors. They can delete the wrong same-timestamp author even when a new sender names the exact target. Symmetric delete-for-both requires peers and linked devices on the same updated RC; there is no mixed-version guarantee. New receivers treat an absent author as authenticated sender-only, so an old sender cannot delete the new receiver's own message through that legacy control.

Changed flow
Generated Delete schema -> builders -> ConversationHandle/anonymous senders -> DM parse/control dispatch -> DmContent/InboxEvent -> InboxEventProcessor -> exact-author MessageService or AnonDmService -> typed scoped tombstone -> actual deleted author in domain event. Channels validate at control dispatch; groups validate at common anonymous dispatcher and typed storage lookup.
