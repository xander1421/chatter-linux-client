  <action>Implement Tenor v2 API client:

     - `api_key: String` (Tenor API key from config)

     - `base_url: &'static str = "https://tenor.googleapis.com/v2"`

  3. Create GifResult struct:
     - `id: String` (Tenor media ID)
     - `title: String` (content description)
     - `preview_url: String` (nanogif or tinygif URL for thumbnails)
     - `url: String` (gif or mediumgif URL for sending)
     - `width: u32`, `height: u32` (dimensions)

  4. Implement methods:
     - `new(api_key: String) -> Self` - create client with reqwest::Client::new()
     - `async fn search(&self, query: &str, limit: u32) -> Result<Vec<GifResult>, MediaError>`
       - Call: GET /search?q={query}&key={key}&limit={limit}&media_filter=gif,tinygif
       - Parse response.results into GifResult vec
     - `async fn trending(&self, limit: u32) -> Result<Vec<GifResult>, MediaError>`
       - Call: GET /featured?key={key}&limit={limit}&media_filter=gif,tinygif
     - `async fn get_by_id(&self, id: &str) -> Result<Option<GifResult>, MediaError>`
       - Call: GET /posts?key={key}&ids={id}&media_filter=gif,tinygif

  5. Response parsing:
     - Tenor v2 returns `results` array with `media_formats` map
     - Extract `gif` format for full size, `tinygif` for preview
     - Each format has `url`, `dims` (width, height array)

  Avoid: Custom User-Agent (Tenor doesn't require it). Don't implement pagination yet (can add later if needed).</action>

<task type="auto">
  <name>Task 2: Implement GifCache with LRU eviction</name>
  <files>src/media/gif/cache.rs</files>
  <action>Implement in-memory LRU cache for GIF metadata and search results:

  1. Create GifCache struct:
     - `search_cache: parking_lot::Mutex<LruCache<String, Vec<GifResult>>>` - query -> results
     - `trending_cache: parking_lot::Mutex<Option<(Instant, Vec<GifResult>)>>` - cached trending with timestamp
     - `max_search_entries: usize` (default 100)
     - `trending_ttl: Duration` (default 5 minutes)

  2. Implement simple LruCache inline (avoid adding new dependency):
     - Use `IndexMap<K, V>` from indexmap (already transitive dep) OR
     - Use `Vec<(K, V)>` with manual eviction for simplicity
     - Actually: Use std collections - `HashMap<String, (Instant, Vec<GifResult>)>` with TTL-based eviction

  3. Create CachedSearchResults:
     - `results: Vec<GifResult>`
     - `cached_at: Instant`

  4. Implement methods:
     - `new() -> Self` - default capacities
     - `with_capacity(search_entries: usize, trending_ttl: Duration) -> Self`
     - `get_search(&self, query: &str) -> Option<Vec<GifResult>>` - return if not expired (1 min TTL)
     - `put_search(&self, query: &str, results: Vec<GifResult>)` - store with timestamp, evict oldest if over capacity
     - `get_trending(&self) -> Option<Vec<GifResult>>` - return if not expired
     - `put_trending(&self, results: Vec<GifResult>)` - store with timestamp
     - `clear(&self)` - clear all caches

  5. Cache key normalization:
     - Lowercase the query
     - Trim whitespace

  Avoid: Complex LRU implementation - use simple HashMap with TTL-based expiry and size limit. Don't persist to disk (in-memory only).</action>
  <verify>cargo check --lib passes, GifCache compiles</verify>
  <done>GifCache provides TTL-based caching for search and trending results</done>
