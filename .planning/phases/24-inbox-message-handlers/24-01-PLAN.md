  <name>Task 1: Define handler traits and common types</name>
  <files>src/inbox/handlers/mod.rs</files>
  <action>
Define the handler infrastructure:

1. **InboxHandler trait** - common interface for all handlers:
   ```rust
   #[async_trait::async_trait]
   pub trait InboxHandler: Send + Sync {
       /// Handle a processed message, returning domain events.
       async fn handle(&self, message: &ProcessedMessage, ctx: &HandlerContext) -> HandlerResult;

       /// Content types this handler processes.
       fn content_types(&self) -> &[ContentType];
   }
   ```

2. **HandlerContext** - shared context for handlers:
   - `local_user_id: UserId` - current user for sender detection
   - `event_tx: broadcast::Sender<DomainEvent>` - emit domain events
   - Stateless, passed to each handle() call

3. **HandlerResult** type alias: `Result<HandlerOutcome, HandlerError>`

4. **HandlerOutcome** enum:
   - `Processed` - successfully handled, ack to server
   - `Ignored` - not relevant (wrong content type), skip
   - `Deferred { reason: String }` - needs retry later

5. **HandlerError** enum:
   - `ParseFailed { error: String }` - protobuf decode failed
   - `ValidationFailed { reason: String }` - content invalid
   - `MissingContext { field: String }` - required data missing

6. **DomainEvent** enum (initial variants, more added in 24-02/24-03):
   - `MessageReceived { message: Message }` - new chat message
   - `MessageEdited { message_id: MessageId, new_content: MessageContent }` - edit
   - `MessageDeleted { message_id: MessageId, author_id: UserId }` - delete
   - `AttachmentReady { attachment: Attachment, message_id: MessageId }` - file metadata

Update existing ContentType enum re-export if needed.

Implement ChatHandler to process DataMessage content:

1. **ChatHandler** struct:
   - No fields (stateless handler pattern)

2. **InboxHandler impl**:
   - `content_types()` returns `[ContentType::DataMessage]`
   - `handle()` decodes and processes DataMessage

3. **handle() implementation**:
   ```rust
   async fn handle(&self, message: &ProcessedMessage, ctx: &HandlerContext) -> HandlerResult {
       // 1. Decode Content proto from plaintext
       let content: Content = prost::Message::decode(message.plaintext.as_slice())
           .map_err(|e| HandlerError::ParseFailed { error: e.to_string() })?;

       // 2. Extract DataMessage from oneof
       let data_message = match content.content {
           Some(content::Content::DataMessage(dm)) => dm,
           _ => return Ok(HandlerOutcome::Ignored),
       };

       // 3. Check for delete request
       if let Some(delete) = &data_message.delete {
           return self.handle_delete(delete, message, ctx).await;
       }

       // 4. Build domain Message
       let msg = self.build_message(&data_message, message, ctx)?;

       // 5. Emit event
       let _ = ctx.event_tx.send(DomainEvent::MessageReceived { message: msg });

       Ok(HandlerOutcome::Processed)
   }
   ```

4. **build_message() helper**:
   - Map channel_id from DataMessage or derive from sender
   - Map sender_id from ProcessedMessage.sender_address
   - Parse body into MessageContent::Text
   - Handle quote/reply_to if present
   - Handle attachments list (AttachmentPointer -> AttachmentId)
   - Handle ephemeral settings (ephemeral, ephemeral_ttl_seconds)
   - Handle AI mentions (targets_ai_bot, mentioned_integrations)

5. **handle_delete() helper**:
   - Extract target_sent_timestamp from Delete
   - Emit DomainEvent::MessageDeleted
   - Return HandlerOutcome::Processed

6. **Error handling**:
   - Missing sender for non-sealed-sender -> HandlerError::MissingContext
   - Invalid channel_id -> HandlerError::ValidationFailed

Implement AttachmentHandler for standalone attachment messages:

1. **AttachmentHandler** struct (stateless):
   - No fields

2. **InboxHandler impl**:
   - `content_types()` returns custom content type for standalone attachments
   - Note: Most attachments come embedded in DataMessage. Standalone AttachmentMessage is for:
     - Large file metadata sent separately
     - Attachment re-sync across devices

3. **handle() implementation**:
   ```rust
   async fn handle(&self, message: &ProcessedMessage, ctx: &HandlerContext) -> HandlerResult {
       let content: Content = prost::Message::decode(message.plaintext.as_slice())
           .map_err(|e| HandlerError::ParseFailed { error: e.to_string() })?;

       let attachment_msg = match content.content {
           Some(content::Content::Attachment(am)) => am,
           _ => return Ok(HandlerOutcome::Ignored),
       };

       // Build Attachment domain object
       let attachment = self.build_attachment(&attachment_msg, message)?;

       // Emit event
       let _ = ctx.event_tx.send(DomainEvent::AttachmentReady {
           attachment,
           message_id: MessageId::from_string(attachment_msg.message_id.clone()),
       });

       Ok(HandlerOutcome::Processed)
   }
   ```

4. **build_attachment() helper**:
   - Map AttachmentPointer fields to domain Attachment:

     - `file_name` -> original filename
     - `size` -> file size in bytes
     - `width/height` -> for images
   - Generate new AttachmentId
   - Set upload_status to Pending (needs download)
