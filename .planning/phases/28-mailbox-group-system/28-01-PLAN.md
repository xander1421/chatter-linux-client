**Established patterns:**
- DmMailbox: Ed25519 keypair (32-byte public, 64-byte private), blind signature, expiry tracking
- DmConversationManager: Load/save with while loop for rusqlite iteration
- RFC 3339 timestamps for SQLite storage
- UNIQUE constraints on (group_id, user_id) for member mailbox tracking
- Challenge-response auth reusing mailbox Ed25519 key

**Key decisions from prior phases:**
- 64-byte Ed25519 private key storage (full keypair bytes)
- Token consumption after successful mailbox creation
- While loop pattern for list queries (avoids rusqlite lifetime issues)

  <action>
Create migration v013 with tables for group mailbox state:

1. `group_mailboxes` - Our mailbox for each group we're in:
   - id TEXT PRIMARY KEY
   - group_id TEXT NOT NULL (ChannelId)
   - mailbox_public_key BLOB NOT NULL (32 bytes Ed25519)
   - mailbox_private_key BLOB NOT NULL (64 bytes Ed25519 keypair)
   - signature BLOB NOT NULL (RSA unblinded signature)
   - randomizer BLOB (optional, for signature verification)
   - token_id TEXT NOT NULL (tracking which token was used)
   - created_at TEXT NOT NULL (RFC 3339)
   - expires_at TEXT NOT NULL (RFC 3339)
   - last_polled_at TEXT (RFC 3339, nullable)
   - UNIQUE(group_id) -- one mailbox per group

2. `group_member_mailboxes` - Peer mailboxes for group members:
   - id TEXT PRIMARY KEY
   - group_id TEXT NOT NULL (ChannelId)
   - user_id TEXT NOT NULL (UserId - the member)
   - mailbox_public_key BLOB NOT NULL (32 bytes Ed25519)
   - received_at TEXT NOT NULL (RFC 3339)
   - expires_at TEXT (RFC 3339, nullable if unknown)
   - UNIQUE(group_id, user_id) -- one mailbox per member per group

Create indexes on group_id for efficient queries.

Register migration in mod.rs MIGRATIONS array as (13, v013_group_mailboxes::migrate).

Follow same pattern as v012_dm_conversations.rs.
  </action>

<task type="auto">
  <name>Task 3: Implement GroupMailboxManager for persistence</name>
  <files>src/mailbox/group/member_mailbox.rs, src/mailbox/group/mod.rs</files>
  <action>
Add GroupMailboxManager (in same file as types, following DM pattern):

```rust
pub struct GroupMailboxManager {
    db: Arc<Database>,
}
```

Methods (mirror DmConversationManager pattern):

1. `load_group_state(&self, group_id: &ChannelId) -> Result<Option<GroupMailboxState>, MailboxError>`
   - Load our_mailbox from group_mailboxes
   - Load all member_mailboxes from group_member_mailboxes
   - Return None if no state exists

2. `save_our_mailbox(&self, mailbox: &GroupMailbox) -> Result<(), MailboxError>`
   - INSERT OR REPLACE into group_mailboxes

3. `save_member_mailbox(&self, group_id: &ChannelId, mailbox: &MemberMailbox) -> Result<(), MailboxError>`
   - INSERT OR REPLACE into group_member_mailboxes

4. `remove_member_mailbox(&self, group_id: &ChannelId, user_id: &UserId) -> Result<(), MailboxError>`
   - DELETE from group_member_mailboxes

5. `update_poll_time(&self, mailbox_id: &str) -> Result<(), MailboxError>`
   - UPDATE last_polled_at

6. `get_all_group_mailboxes(&self) -> Result<Vec<(ChannelId, [u8; 32], [u8; 64], String)>, MailboxError>`
   - Return (group_id, public_key, private_key, mailbox_id) for all active groups
   - Used for batch polling

7. `get_expiring_group_mailboxes(&self, within_hours: i64) -> Result<Vec<ChannelId>, MailboxError>`
   - Return groups needing mailbox refresh

8. `cleanup_expired(&self) -> Result<u32, MailboxError>`
   - Delete expired mailboxes, return count

9. `delete_group_state(&self, group_id: &ChannelId) -> Result<(), MailboxError>`
   - Delete all state for a group (when leaving)

Use while loop pattern for list queries (same as DmConversationManager).
Use RFC 3339 for timestamp storage.

Update mod.rs to export GroupMailbox, MemberMailbox, GroupMailboxState, GroupMailboxManager.
