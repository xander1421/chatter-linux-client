<task type="auto">
  <name>Task 2: Quote/reply operation</name>
  <files>src/services/message_service.rs</files>
  <action>
Add send_reply method to MessageService:

`send_reply(&self, message_client, channel_id, reply_to_id, text, attachment_ids, mentioned_integrations, targets_ai_bot) -> Result<Message, MessageError>`

Implementation:
1. Check logged in
2. Validate reply_to_id exists in local storage (informational only - server validates)
3. Validate content (must have text or attachments)
4. Build proto content as in send_message
5. Call message_client.send_message() but with parent_id = None (reply_to is separate from threading)
6. After getting response, manually set reply_to field on domain message before storing
7. Store in local storage
8. Return message

Note: The proto Message doesn't have a separate reply_to field - replies are handled client-side by storing the reference. The server's parent_id is for threads. Quote/reply is a client feature that stores the quoted message reference locally for display.

Modify proto_to_domain_message to accept optional reply_to parameter for this case.
  </action>
  <verify>cargo build --lib 2>&1 | grep -E "^error" || echo "Build OK"</verify>
  <done>send_reply method compiles and correctly sets reply_to on returned message</done>

<task type="auto">
  <name>Task 3: Forward message operation</name>
  <files>src/services/message_service.rs</files>
  <action>
Add forward_message method to MessageService:

`forward_message(&self, message_client, source_message_id, target_channel_id, optional_comment) -> Result<Message, MessageError>`

Implementation:
1. Check logged in
2. Get source message from local storage (must exist)
3. Extract text content from source message using as_text()
4. Build forwarded content:
   - If optional_comment provided: format as "[comment]\n\n---\nForwarded:\n[original_text]"
   - If no comment: format as "Forwarded:\n[original_text]"
5. Include original attachments if source has them (copy attachment_ids)
6. Call message_client.send_message() to target_channel_id with forwarded content
7. Convert response and store locally
8. Return the new forwarded message

Note: This is a simple text-based forward. The forwarded message is a new message with attribution text. Server doesn't have special forward handling - it's a client-side convention.
