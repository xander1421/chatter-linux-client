Implement KeyExchangeHandler following the established pattern:

1. Parse Content proto from plaintext, extract KeyExchange variant
2. Validate: ephemeral_pk must be 32 bytes (Ed25519), conversation_id non-empty
3. Extract sender from ProcessedMessage.sender_address (required for key exchange)
4. Add new DomainEvent::KeyExchangeReceived with fields:
   - sender_id: UserId (from sender address)
   - conversation_id: ChannelId (parse from string)
   - ephemeral_public_key: [u8; 32]
   - timestamp: u64
5. Emit event via ctx.emit()
6. Return HandlerOutcome::Processed

Note: Actual key processing deferred to Phase 27 (Mailbox DM System). This handler just parses and emits.

<task type="auto">
  <name>Task 3: Implement PinHandler for message pin/unpin events</name>
  <files>src/inbox/handlers/pin.rs</files>
  <action>
Implement PinHandler for PinMessage proto:

1. Parse Content proto from plaintext, extract Pin variant
2. Validate: target_author_aci non-empty, channel_id non-empty, target_sent_timestamp > 0
3. Get pinner from ProcessedMessage.sender_address (or use local_user_id for sealed sender)
4. Convert target_sent_timestamp to MessageId using uuid_from_timestamp pattern
5. Emit DomainEvent based on unpin flag:
   - If unpin=false: emit MessagePinned { message_id, pinner_id, channel_id }
   - If unpin=true: emit MessageUnpinned { message_id, unpinner_id, channel_id }
6. Return HandlerOutcome::Processed

Note: DomainEvent::MessagePinned and MessageUnpinned already exist in mod.rs from Phase 24.

For content_types(), use ContentType::DataMessage (Pin is embedded in Content oneof like Reaction).

Add unit tests:
- Pin message event
- Unpin message event
- Missing channel_id (validation error)
- Wrong content type (Ignored)
  </action>
  <verify>cargo build --lib && cargo test --lib pin -- --nocapture</verify>
  <done>PinHandler compiles, tests pass, emits MessagePinned/MessageUnpinned events</done>
