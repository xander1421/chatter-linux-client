<task type="auto">
  <name>Task 1: Implement StreamingState for real-time data</name>
  <files>src/state/streaming_state.rs</files>
  <action>
Replace the stub StreamingState with a full Store<StreamingStateData> wrapper.

StreamingStateData fields:
- typing_by_channel: HashMap<ChannelId, Vec<UserId>> - who is typing per channel
- recent_reactions: HashMap<MessageId, Vec<ReactionSummary>> - recent reactions per message (limited cache)
- last_typing_update: Option<Instant> - for staleness detection

ReactionSummary struct (simplified for UI):
- emoji: String
- count: u32
- user_reacted: bool (whether current user reacted)

Methods to implement:
- new() -> Self
- get_typing_users(channel_id: &ChannelId) -> Vec<UserId>
- set_typing_users(channel_id: ChannelId, users: Vec<UserId>) - updates and notifies
- clear_typing(channel_id: &ChannelId) - clears typing for channel
- get_reactions(message_id: &MessageId) -> Option<Vec<ReactionSummary>>
- set_reactions(message_id: MessageId, reactions: Vec<ReactionSummary>)
- update_reaction(message_id: &MessageId, emoji: String, delta: i32, user_reacted: Option<bool>) - increment/decrement
- subscribe() -> broadcast::Receiver<StreamingStateData>
- clear() - reset all state

Note: This state is a simplified view for UI. The TypingAggregator and ReactionAggregator in the network layer handle the raw stream processing. Services will bridge from aggregators to this state.

Add unit tests covering:
- Typing user updates and clear
- Reaction summary updates with count changes
- Subscribe receives notifications
