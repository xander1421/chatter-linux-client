**Tech stack available:**
- libsignal-protocol (IdentityKeyPair, PreKeyBundle, process_prekey_bundle, session_cipher)
- SignalStore implements all 6 libsignal storage traits
- KeyStore provides SQLite-backed CRUD for all key types
- rand 0.9 for secure random generation

**Established patterns:**
- SignalStore wraps KeyStore, implements libsignal traits
- Address format: "name:device_id" for ProtocolAddress
- StorageCallbackError wrapper for UnwindSafe compatibility
- TOFU identity verification

**Constraining decisions:**
- Phase 10: TOFU (Trust On First Use) for identity verification
- Phase 9: BLOB columns for all crypto data (binary efficiency)

**Critical Note (from libsignal source):**
libsignal no longer supports X3DH - only PQXDH (post-quantum). The process_prekey_bundle
function requires Kyber prekeys. This is why Phase 12 (Prekeys) includes Kyber prekey
generation. For now, we implement the session manager API that will work once prekeys exist.

<task type="auto">
  <name>Task 1: Implement IdentityKeyManager</name>
  <files>src/crypto/signal/identity.rs</files>
  <action>
Implement IdentityKeyManager with:

1. **Struct definition:**
   - `key_store: Arc<KeyStore>` - for identity persistence

2. **Methods:**
   - `new(key_store: Arc<KeyStore>) -> Self`
   - `generate_identity(rng: &mut impl CryptoRng + Rng) -> Result<(u32, IdentityKeyPair), CryptoError>`:
     - Generate registration_id using rng.gen::<u32>() % 0x3FFF (14 bits, Signal spec)
     - Generate IdentityKeyPair using IdentityKeyPair::generate(rng)
     - Store via key_store.set_local_identity(registration_id, &key_pair.serialize())
     - Return (registration_id, key_pair)
   - `get_identity() -> Result<Option<(u32, IdentityKeyPair)>, CryptoError>`:
     - Call key_store.get_local_identity()
     - Deserialize bytes to IdentityKeyPair if exists
   - `has_identity() -> Result<bool, CryptoError>`:
     - Delegate to key_store.has_local_identity()
   - `get_public_key() -> Result<IdentityKey, CryptoError>`:
     - Get identity and return the public key portion

**Imports needed:**
```rust
use libsignal_protocol::{IdentityKey, IdentityKeyPair};
use rand::{CryptoRng, Rng};
use std::sync::Arc;
use crate::error::CryptoError;
use crate::storage::KeyStore;
```

**Registration ID notes:**
Signal uses 14-bit registration IDs (0-16383). Generate with `rng.gen::<u32>() % 0x3FFF + 1` to avoid zero.

**Error handling:**
Map StorageError to CryptoError::Storage variant. Return CryptoError::NoIdentity when identity required but missing.

<task type="auto">
  <name>Task 2: Implement SessionManager</name>
  <files>src/crypto/signal/session.rs</files>
  <action>
Implement SessionManager with:

1. **Struct definition:**
   - `signal_store: Arc<Mutex<SignalStore>>` - Mutex needed because libsignal traits take &mut self

2. **Methods:**
   - `new(signal_store: Arc<Mutex<SignalStore>>) -> Self`

   - `async establish_session(remote_address: &ProtocolAddress, bundle: &PreKeyBundle, rng: &mut impl CryptoRng + Rng) -> Result<(), CryptoError>`:
     - Lock the store
     - Call `libsignal_protocol::process_prekey_bundle(remote_address, &mut *store, &mut *store, bundle, SystemTime::now(), rng).await`
     - Map errors to CryptoError

   - `async has_session(remote_address: &ProtocolAddress) -> Result<bool, CryptoError>`:
     - Lock store, call store.load_session(remote_address).await
     - Return Ok(session.is_some())

   - `async get_session(remote_address: &ProtocolAddress) -> Result<Option<SessionRecord>, CryptoError>`:
     - Lock store, call store.load_session(remote_address).await

   - `generate_fingerprint(local_id: &str, local_key: &IdentityKey, remote_id: &str, remote_key: &IdentityKey) -> Result<String, CryptoError>`:
     - Use libsignal_protocol::Fingerprint::new()
     - Version 2, 5200 iterations (Signal spec)
     - Return display_string()

**Imports needed:**
```rust
use libsignal_protocol::{
    Fingerprint, IdentityKey, PreKeyBundle, ProtocolAddress, SessionRecord,
    process_prekey_bundle, SessionStore,
};
use rand::{CryptoRng, Rng};
use std::sync::{Arc, Mutex};
use std::time::SystemTime;
use crate::crypto::SignalStore;
use crate::error::CryptoError;
```

**Mutex rationale:**
libsignal store traits require &mut self. We use std::sync::Mutex (not tokio::sync::Mutex) because:
1. The async trait methods in libsignal are #[async_trait(?Send)] (not Send)
2. We hold the lock briefly during each operation
3. SignalStore operations are synchronous internally

**Fingerprint format:**
Signal uses 5200 iterations for fingerprint generation. The displayable string is a 60-digit number.
