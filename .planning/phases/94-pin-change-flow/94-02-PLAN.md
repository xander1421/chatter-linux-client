**SvrBackupService** — Add method:
```rust
pub async fn change_pin_backup(
    &self,
    old_svr_secret: &[u8; 32],
    new_svr_secret: &[u8; 32],
    identity_keypair: &[u8; 64],
    profile_key: &[u8; 32],
    new_registration_lock: &[u8; 32],
    new_svr_public_key: &[u8; 32],
) -> Result<(), SvrBackupError>
```

Flow:
1. Derive old_backup_id_hash from old_svr_secret
2. Create KeyBackupPayload from identity_keypair + profile_key
3. Encrypt with new_svr_secret → new ciphertext
4. Derive new_backup_id_hash from new_svr_secret
5. Get current version from settings, increment
6. Call SvrClient::change_pin_backup with all fields
7. Store confirmed version in settings
8. Zeroize intermediates

**ChatterClient** — Add public method:
```rust
pub async fn change_pin(
    &self,
    old_pin: &str,
    new_pin: &str,
    username: &str,
) -> Result<(), ClientError>
```

Flow:
1. Validate both PINs (6 digits)
2. Get identity keypair from signal store (same pattern as retry_svr_backup)
3. Get profile key from settings
4. Derive old_svr_secret from old_pin + username
5. Derive new_svr_secret from new_pin + username
6. Derive new_registration_lock from new_pin + username
7. Generate new SvrKeypair from new_pin + username, get public key bytes
8. Call svr_backup().change_pin_backup(old_svr_secret, new_svr_secret, identity_keypair, profile_key, new_registration_lock, new_svr_public_key)
9. Zeroize ALL sensitive intermediates (both svr_secrets, identity_keypair, profile_key, registration_lock)
10. Return Ok(())

Error handling: Return ClientError on failure, zeroize on all paths.
