<objective>
Create CurrentUserProvider trait to eliminate 13+ duplicate `current_user_id()` implementations across services.

Purpose: Centralize the "get current logged-in user" cross-cutting concern into a single trait implementation, reducing code duplication and providing a consistent API across all services.

Output: A `CurrentUserProvider` trait in `src/services/` that all services can use instead of duplicating the settings_repo lookup pattern.
</objective>

**Problem:** 13+ services implement identical `current_user_id()`:
- typing_service.rs
- channel/service/mod.rs
- message/mod.rs
- search_service.rs
- ai_summarize.rs
- ai_service.rs
- saved_message_service.rs
- reaction_service.rs
- moderation_service.rs
- read_receipt_service.rs
- presence_service.rs
- draft_service.rs
- user_service.rs

Each contains:
```rust
fn current_user_id(&self) -> Result<UserId, SomeError> {
    let user_id_str = self
        .settings_repo
        .get_string(keys::CURRENT_USER_ID)
        .map_err(SomeError::Storage)?
        .ok_or(SomeError::NotLoggedIn)?;
    user_id_str.parse().map_err(|_| SomeError::NotLoggedIn)
}
```

**Solution:** Create a trait that provides this functionality, then have services use it.
</context>

    #[error("not logged in")]

}

3. An implementation for SettingsRepository:
```rust
impl CurrentUserProvider for SettingsRepository {
    fn current_user_id(&self) -> Result<UserId, CurrentUserError> {
        let user_id_str = self
            .get_string(keys::CURRENT_USER_ID)
            .map_err(CurrentUserError::Storage)?
            .ok_or(CurrentUserError::NotLoggedIn)?;
        user_id_str.parse().map_err(|_| CurrentUserError::NotLoggedIn)
    }
}
```

4. Add `pub mod current_user;` to `src/services/mod.rs` and re-export `pub use current_user::{CurrentUserProvider, CurrentUserError};`
