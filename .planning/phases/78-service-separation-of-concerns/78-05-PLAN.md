**Current state after Plans 01-04:**
- CurrentUserProvider trait eliminates 13 duplicate implementations
- ChannelEventService handles member join/leave system messages
- DmBootstrapService handles DM channel establishment
- UI layer no longer directly accesses repositories for mutations

**Remaining items:**
1. Network validation (src/network/validation/) - currently validates messages before they reach services
2. Consider whether this validation should move to services or remain as transport-level filtering

**Analysis:**
The network validation layer (validator.rs, deduplicator.rs, orderer.rs) handles:
- Message ID validation
- Timestamp validation
- Deduplication
- Ordering

These are actually appropriate at the network layer because:
- They're about message transport integrity, not business rules
- They filter invalid/duplicate messages before they consume service resources
- Moving them would add latency to every message

**Decision:** Keep network validation as-is (it's doing transport-level validation, which is correct).
Focus this plan on cleanup and ensuring the offline_queue inconsistency is resolved.
</context>
