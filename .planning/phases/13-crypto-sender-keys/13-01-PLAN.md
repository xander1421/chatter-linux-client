**libsignal sender key API (from ~/.cargo/registry):**
```rust
// Create SKDM for a new group or to refresh sender key
pub async fn create_sender_key_distribution_message<R: Rng + CryptoRng>(
    sender: &ProtocolAddress,
    distribution_id: Uuid,
    sender_key_store: &mut dyn SenderKeyStore,
    csprng: &mut R,
) -> Result<SenderKeyDistributionMessage>

// Process received SKDM from another group member
pub async fn process_sender_key_distribution_message(
    sender: &ProtocolAddress,
    skdm: &SenderKeyDistributionMessage,
    sender_key_store: &mut dyn SenderKeyStore,
) -> Result<()>

// Encrypt message for group (all members who have our sender key can decrypt)
pub async fn group_encrypt<R: Rng + CryptoRng>(
    sender: &ProtocolAddress,
    distribution_id: Uuid,
    plaintext: &[u8],
    sender_key_store: &mut dyn SenderKeyStore,
    csprng: &mut R,
) -> Result<CiphertextMessage>

// Decrypt message from group member
pub async fn group_decrypt(
    skm: &[u8],
    sender_key_store: &mut dyn SenderKeyStore,
    sender: &ProtocolAddress,
) -> Result<Vec<u8>>
```

   ```rust
   /// Create a sender key distribution message for a group.
   /// Call this when joining a group or when rotating sender keys.
   /// The returned SKDM must be sent to all group members via their individual sessions.
   pub async fn create_distribution_message(
       sender: &ProtocolAddress,
       distribution_id: Uuid,
       sender_key_store: &mut dyn SenderKeyStore,
   ) -> Result<SenderKeyDistributionMessage, CryptoError>

   /// Process a received sender key distribution message from a group member.
   /// Call this when receiving an SKDM from another member.
   /// After processing, you can decrypt messages from that sender.
   pub async fn process_distribution_message(
       sender: &ProtocolAddress,
       skdm: &SenderKeyDistributionMessage,
       sender_key_store: &mut dyn SenderKeyStore,
   ) -> Result<(), CryptoError>

   /// Encrypt a message for a group using sender keys.
   /// All members who have processed our distribution message can decrypt.
   pub async fn encrypt(
       sender: &ProtocolAddress,
       distribution_id: Uuid,
       plaintext: &[u8],
       sender_key_store: &mut dyn SenderKeyStore,
   ) -> Result<CiphertextMessage, CryptoError>

   /// Decrypt a group message from a sender.
   /// Requires having previously processed that sender's distribution message.
   pub async fn decrypt(
       ciphertext: &[u8],
       sender: &ProtocolAddress,
       sender_key_store: &mut dyn SenderKeyStore,
   ) -> Result<Vec<u8>, CryptoError>
   ```

5. Each method:
   - Creates thread_rng() for methods that need RNG (create_distribution_message, encrypt)
   - Calls the corresponding libsignal function
   - Maps SignalProtocolError to CryptoError::Protocol variant

Note: Methods are async because libsignal's functions are async. The actual store operations are sync but wrapped in async.

Avoid: Don't store the sender_key_store in the struct (stateless pattern from Phase 11). Don't create custom distribution message types (use libsignal's SenderKeyDistributionMessage directly).
