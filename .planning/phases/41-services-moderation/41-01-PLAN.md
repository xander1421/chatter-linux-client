**Established patterns:**
- Service takes Arc<SettingsRepository> and Arc<ChannelRepository> dependencies
- current_user_id() helper for auth check via settings repo
- Streaming RPC consumption: while let loop with event variant matching
- ChannelClient methods already exist: kick_user, ban_user, unban_user
- Domain types: Ban, Mute, ModerationLogEntry, ModerationAction
- Proto types: ChannelModeration, channel_moderation::Action

**Key decisions:**
- kick_user, ban_user, unban_user already exist as helpers in ChannelService
- ModerationService wraps these with higher-level logic (permission checks, local tracking)
- Mutes always require expiry duration (unlike permanent bans)
- Used uuid::Uuid for moderation IDs (no special types)
- Mutes are tracked via membership.is_muted and membership.muted_until fields
