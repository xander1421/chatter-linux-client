**Established patterns:**
- parking_lot::RwLock for sync contexts
- broadcast channels for events (capacity 16-256)
- Result<T, E> for fallible operations
- Stateless manager pattern for crypto operations

**Constraining decisions:**
- Phase 22: MessageValidationPipeline uses PipelineResult enum (Ready/Buffered/Duplicate/Invalid)
- Phase 19: MailboxClient uses challenge-response auth for poll/acknowledge
- Phase 14: SealedSenderManager is stateless, takes stores as parameters

**Note:** This phase implements the device inbox polling infrastructure. The ephemeral mailbox system (blind signatures, anonymous mailboxes) is Phase 26-29. This phase focuses on the core polling loop and message receipt coordination.

  <action>
Create configuration and event types for the inbox system:

1. **InboxConfig** struct with:
   - `poll_interval: Duration` - base polling interval (default 5 seconds)
   - `poll_interval_idle: Duration` - interval when idle (default 30 seconds)
   - `max_batch_size: u32` - max messages per poll (default 100)
   - `retry_attempts: u32` - retries for failed messages (default 3)
   - `ack_batch_size: u32` - messages to ack per request (default 50)
   - Builder pattern with `InboxConfig::builder().poll_interval(...).build()`
   - `InboxConfig::default()` with sensible defaults

2. **InboxEvent** enum with broadcast variants:
   - `MessageReceived { message_id: String, envelope_type: EnvelopeType }` - new message arrived
   - `MessageProcessed { message_id: String }` - successfully processed
   - `MessageFailed { message_id: String, error: String }` - processing failed
   - `PollCompleted { count: u32, has_more: bool }` - poll cycle complete
   - `PollFailed { error: String }` - poll request failed
   - `AcknowledgeFailed { message_ids: Vec<String>, error: String }` - ack failed

3. **InboxState** enum:
   - `Idle` - not polling
   - `Polling` - active poll in progress
   - `Processing` - processing received messages
   - `Stopped` - explicitly stopped

4. **InboxStats** struct for monitoring:
   - `messages_received: u64`
   - `messages_processed: u64`
   - `messages_failed: u64`
   - `last_poll_at: Option<Instant>`
   - `last_poll_count: u32`

Use `parking_lot::RwLock` for stats access. Event channel capacity 64.

<task type="auto">
  <name>Task 2: Implement InboxPoller with configurable polling loop</name>
  <files>src/inbox/poller.rs</files>
  <action>
Implement the polling loop that fetches messages from the server:

1. **InboxPoller** struct with:
   - `config: InboxConfig`
   - `mailbox_client: Arc<Mutex<MailboxClient>>` - for RPC calls
   - `mailbox_keypair: (Vec<u8>, Vec<u8>)` - (public_key, private_key) for auth
   - `state: Arc<RwLock<InboxState>>`
   - `stats: Arc<RwLock<InboxStats>>`
   - `event_tx: broadcast::Sender<InboxEvent>`
   - `shutdown_rx: watch::Receiver<bool>`
   - `last_message_id: Arc<RwLock<Option<String>>>` - for pagination

2. **Constructor**: `InboxPoller::new(config, mailbox_client, keypair, shutdown_rx)`

3. **poll_once()** method:
   - Get challenge: `mailbox_client.get_mailbox_challenge(public_key)`
   - Sign challenge with private key (Ed25519)
   - Call `poll_ephemeral_mailbox(public_key, signature, challenge, after_message_id, limit)`
   - Return `Vec<EphemeralMessage>` and `has_more` flag
   - Update stats and emit `PollCompleted` event
   - On error, emit `PollFailed` and return error

4. **run()** async method - the main polling loop:
   ```rust
   pub async fn run(&self) -> Result<(), InboxError> {
       loop {
           tokio::select! {
               _ = self.shutdown_rx.changed() => {
                   if *self.shutdown_rx.borrow() {
                       self.set_state(InboxState::Stopped);
                       return Ok(());
                   }
               }
               _ = tokio::time::sleep(self.current_interval()) => {
                   self.set_state(InboxState::Polling);
                   match self.poll_once().await {
                       Ok(messages) => {
                           // Emit MessageReceived for each
                           // Update last_message_id
                       }
                       Err(e) => {
                           // Log and continue (don't crash on poll failure)
                       }
                   }
                   self.set_state(InboxState::Idle);
               }
           }
       }
   }
   ```

5. **current_interval()** - returns `poll_interval` if recent activity, `poll_interval_idle` otherwise

6. **acknowledge()** method:
   - Take message IDs to acknowledge
   - Get fresh challenge, sign, call `acknowledge_messages()`
   - Emit `AcknowledgeFailed` on error

For Ed25519 signing, use `ed25519_dalek` crate (already in deps via libsignal).

Implement the main coordinator that orchestrates inbox operations:

1. **DeviceInboxProvider** struct with:
   - `config: InboxConfig`
   - `poller: Arc<InboxPoller>`
   - `pipeline: Arc<MessageValidationPipeline>`
   - `event_tx: broadcast::Sender<InboxEvent>`
   - `shutdown_tx: watch::Sender<bool>`
   - `poller_handle: Option<JoinHandle<()>>` - background task handle

2. **Constructor**: `DeviceInboxProvider::new(config, mailbox_client, keypair, pipeline)`
   - Create shutdown channel
   - Create event broadcast channel
   - Create InboxPoller
   - Don't start polling yet (call start() explicitly)

3. **start()** method:
   - Spawn poller.run() as background task
   - Store JoinHandle
   - Return Result indicating success

4. **stop()** method:
   - Send shutdown signal via watch channel
   - Await JoinHandle with timeout
   - Clean shutdown

5. **process_message()** method:
   - Take EphemeralMessage from poll
   - Run through validation pipeline
   - Match on PipelineResult:
     - Ready: emit MessageReceived, return Ok
     - Buffered: return Ok (will be delivered later)
     - Duplicate: log and skip
     - Invalid(reason): emit MessageFailed, return Err
   - This does NOT decrypt - that's Phase 24 handlers

6. **subscribe()** method - returns `broadcast::Receiver<InboxEvent>`

7. **stats()** method - returns clone of InboxStats

8. **Update mod.rs**:
   - Re-export DeviceInboxProvider, InboxConfig, InboxEvent, InboxState, InboxStats
   - Re-export InboxPoller for testing

Add unit tests:
- Test InboxConfig defaults and builder

- Test event emission (mock the client)
