  <action>
Create types for message processing results:

1. **ProcessedMessage** struct representing a successfully processed message:
   - `message_id: String` - original envelope ID
   - `sender_address: Option<ProtocolAddress>` - sender (None for sealed sender until decrypted)
   - `content_type: ContentType` - what kind of content
   - `plaintext: Vec<u8>` - decrypted plaintext (raw bytes, handlers parse)
   - `timestamp: u64` - server timestamp
   - `envelope_type: EnvelopeType` - from proto

2. **ContentType** enum for routing to handlers:
   - `DataMessage` - regular chat message
   - `SyncMessage` - multi-device sync
   - `TypingMessage` - typing indicator
   - `ReceiptMessage` - read/delivery receipt
   - `CallMessage` - call signaling
   - `NullMessage` - keep-alive
   - `SenderKeyDistribution` - group key distribution
   - `DecryptionError` - retry request
   - `Unknown(u32)` - unknown type

3. **ProcessingError** enum:
   - `DecryptionFailed { message_id: String, error: String }` - crypto failure
   - `ValidationFailed { message_id: String, reason: String }` - invalid message
   - `StoreError { message_id: String, error: String }` - storage failure
   - `Duplicate { message_id: String }` - already processed
   - `Expired { message_id: String }` - message too old
   - `UnsupportedEnvelope { message_id: String, envelope_type: i32 }` - unknown type

4. **ProcessingResult** type alias: `Result<ProcessedMessage, ProcessingError>`

Derive Debug, Clone where appropriate. ProcessingError should implement std::error::Error.

<task type="auto">
  <name>Task 2: Implement MessageProcessor for decryption coordination</name>
  <files>src/inbox/processor.rs</files>
  <action>
Implement the processor that coordinates decryption:

1. **MessageProcessor** struct with:
   - `trust_root: PublicKey` - server trust root for sealed sender validation
   - `local_e164: Option<String>` - local phone number
   - `local_uuid: String` - local user UUID
   - `local_device_id: DeviceId` - local device ID

2. **Constructor**: `MessageProcessor::new(trust_root, local_e164, local_uuid, local_device_id)`

3. **process()** async method - main processing entry point:
   ```rust
   pub async fn process<I, S, P, SP, K>(
       &self,
       message: &EphemeralMessage,
       identity_store: &mut I,
       session_store: &mut S,
       pre_key_store: &mut P,
       signed_pre_key_store: &SP,
       kyber_pre_key_store: &mut K,
   ) -> ProcessingResult
   where
       I: IdentityKeyStore,
       S: SessionStore,
       P: PreKeyStore,
       SP: SignedPreKeyStore,
       K: KyberPreKeyStore,
   ```

4. **process() implementation**:
   - Match on envelope_type:
     - `SealedSender`: Use `SealedSenderManager::decrypt()` with stores
     - `PrekeyMessage`: Use libsignal `signalDecryptPreKey()`
     - `Message`: Use libsignal `signalDecrypt()`
     - `Unspecified`: Return `ProcessingError::UnsupportedEnvelope`
   - Extract sender info from decryption result
   - Determine ContentType from decrypted protobuf (peek at type field)
   - Return ProcessedMessage

5. **determine_content_type()** helper:
   - Parse first few bytes of plaintext
   - Look for Content message type field
   - Return appropriate ContentType variant

6. **Handle errors gracefully**:
   - Map CryptoError to ProcessingError::DecryptionFailed
   - Handle SealedSenderSelfSend specially (log warning, skip)
   - Expired certificates -> ProcessingError::Expired

Note: This does NOT route to handlers - it just decrypts and categorizes.
Handlers are Phase 24.
  </action>
  <verify>cargo check --lib 2>&1 | grep -E "^error" || echo "No errors"</verify>
  <done>MessageProcessor.process() handles all envelope types, maps errors correctly, determines content type</done>

<task type="auto">
  <name>Task 3: Implement LocalQueue for retry handling</name>
  <files>src/inbox/queue.rs, src/inbox/mod.rs</files>
  <action>
Implement local queue for messages that fail processing:

1. **QueuedInboxMessage** struct:
   - `message: EphemeralMessage` - the original message
   - `attempts: u32` - number of processing attempts
   - `last_attempt: Instant` - when last tried
   - `next_attempt: Instant` - when to retry
   - `error: Option<String>` - last error message

2. **LocalQueue** struct with:
   - `messages: VecDeque<QueuedInboxMessage>` - pending messages
   - `max_size: usize` - max queue size (default 1000)
   - `max_attempts: u32` - max retries (default 3)
   - `base_delay: Duration` - base retry delay (default 5 seconds)
   - `persistence_path: Option<PathBuf>` - optional persistence file

3. **Methods**:
   - `new(max_size, max_attempts, base_delay, persistence_path)` - constructor
   - `enqueue(message, error)` - add message to retry queue
   - `dequeue_ready() -> Option<QueuedInboxMessage>` - get next message ready for retry
   - `peek_ready() -> Option<&QueuedInboxMessage>` - peek without removing
   - `remove(message_id: &str)` - remove successfully processed message
   - `mark_failed(message_id: &str, error: String)` - increment attempts, update delay
   - `len() -> usize` - queue length
   - `is_empty() -> bool`
   - `clear()` - clear all messages

4. **Exponential backoff for retries**:
   - delay = base_delay * 2^attempts
   - Cap at 5 minutes
   - After max_attempts, emit event and drop message

5. **Persistence** (optional, for crash recovery):
   - `save()` - serialize to JSON, atomic write to file
   - `load()` - deserialize from file on startup
   - Use same atomic .tmp rename pattern as offline_queue.rs

6. **Update mod.rs**:
   - Re-export MessageProcessor, ProcessedMessage, ContentType, ProcessingError
   - Re-export LocalQueue, QueuedInboxMessage

Add unit tests:
- Test enqueue/dequeue
- Test retry backoff calculation
- Test max_attempts behavior
- Test persistence save/load
