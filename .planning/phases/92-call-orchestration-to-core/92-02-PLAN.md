  <action>
1. Add to CallSignalingService:

   `start_anon_dm_call()`:
   - Acquire blind signature token (request 5 more if none available)
   - Send call offer via anon_dm_service.send_call_offer()
   - Mark token as used
   - Store pending anon call in anon_dm_service
   - Return room_name + call_room_id
   - On any failure: store failed call history

   `start_anon_group_call()`:
   - Same flow but via anon_group_service
   - Token from anon_group_service

   `accept_anon_call()`:
   - Take pending call from anon_dm_service
   - Acquire fresh token
   - Send accept answer via anon_dm_service
   - Join anon call room via anon_dm_service
   - Connect to LiveKit via call_worker.connect_with_token()
   - Return CallSetupResult with encryption key + verification emojis

   `handle_anon_call_answer()`:
   - Take pending call (caller side)
   - If accepted: acquire token, join room, connect LiveKit
   - If declined: store declined call history
   - Return CallSetupResult or None

   `decline_anon_call()`:
   - Take pending call
   - Send decline answer
   - Store missed call history

2. Add `AnonCallSetupResult` to domain/call.rs:
   - room_name, channel_id, encryption_key, verification_emojis, is_video

3. Expose through ChatterClient facade methods.

The methods need Arc<AnonDmService> and Arc<AnonGroupService> — these are already on CoreServices, so CallSignalingService needs them injected (add to constructor or pass as params).
  </action>
