# Phase 79-03: Avatar Wiring - Complete Avatar Support

## Overview

Wire avatar support throughout the UI layer. Backend storage and encryption are complete; this phase focuses on:
1. Adding avatar to DomainEvents so UI can access it
2. Displaying peer avatars in anon DM requests and conversations
3. (Optional) Registration and profile edit avatar upload

## Current State

### Completed (Backend)
- `profile_crypto.rs`: `encrypt_avatar()` / `decrypt_avatar()` with AES-256-GCM
- `settings_repo`: `AVATAR` key stores user's own avatar bytes
- `anon_dm_service`: `get_my_avatar()` / `get_encrypted_avatar()` for sharing
- Proto: `encrypted_avatar` field in `AnonDmRequest` and `AnonDmAccept`
- Database: `peer_avatar BLOB` column in `anon_dm_conversations`
- Domain: `AnonDm.peer_avatar: Option<Vec<u8>>`
- Handlers: Decrypt and store peer avatar on receive

### Missing (UI Wiring)
1. DomainEvents don't expose avatar to UI layer
2. UI handlers set `avatar_url: ""` (empty) everywhere
3. No avatar upload in registration or profile edit

### Task 3: Add helper to convert avatar bytes to Slint Image
**File:** `src/bin_ui/converters.rs`

Add function:
```rust
pub fn avatar_bytes_to_image(bytes: &[u8]) -> Option<slint::Image> {
    let img = image::load_from_memory(bytes).ok()?;
    let rgba = img.to_rgba8();
    let (w, h) = rgba.dimensions();
    let buffer = slint::SharedPixelBuffer::<slint::Rgba8Pixel>::clone_from_slice(
        rgba.as_raw(), w, h,
    );
    Some(slint::Image::from_rgba8(buffer))
}
```
