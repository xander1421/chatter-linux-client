<objective>
Stop sending profile_key to server; send only derived UAK.

Purpose: Server should never have profile_key - it can decrypt all profile data. Only UAK (16 bytes derived from profile_key) needed for sealed sender verification.
Output: Client sends UAK instead of profile_key in registration/login flows.
</objective>

**Critical finding from audit:**
- `src/services/auth_service.rs:376` sends `&profile_key` (32 bytes) to server
- `src/network/grpc/auth_client.rs:191` includes `profile_key: profile_key.to_vec()`
- Signal NEVER sends profile_key - only derived UAK (16 bytes)
- Server comment says "UAK is DERIVED from this" - this is the flaw

**Signal's approach (from Signal-Desktop AccountManager.preload.ts):**
- Profile key stays client-side only
- Only `accessKey` (16 bytes) derived via AES-GCM sent to server
- Server stores UAK, not profile_key

**UAK derivation already correct in `device_credentials.rs:174-192`:**
- Uses AES-256-GCM with profile_key as key
- Zero nonce, encrypt 16 zero bytes
- First 16 bytes of ciphertext = UAK
</context>
