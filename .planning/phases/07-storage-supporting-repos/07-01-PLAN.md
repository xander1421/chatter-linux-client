Create v005_attachments.rs with V005Attachments migration implementing:

```sql
CREATE TABLE attachments (
    id TEXT PRIMARY KEY,
    -- File metadata (stored as JSON for nested structure)
    metadata_json TEXT NOT NULL,
    -- Status enum as integer
    status INTEGER NOT NULL DEFAULT 0,
    -- File paths
    local_path TEXT,
    remote_url TEXT,
    -- Encryption data (BLOB for binary)
    encryption_key BLOB,
    encryption_iv BLOB,
    -- Timestamps
    created_at TEXT NOT NULL
);

-- Index for listing attachments by status (pending uploads, etc.)
CREATE INDEX idx_attachments_status ON attachments(status);

-- Thumbnails cache table
CREATE TABLE thumbnails (
    attachment_id TEXT PRIMARY KEY REFERENCES attachments(id) ON DELETE CASCADE,
    local_path TEXT NOT NULL,
    width INTEGER NOT NULL,
    height INTEGER NOT NULL,
    created_at TEXT NOT NULL
);
```

AttachmentStatus integer mapping:
- 0=Pending, 1=Uploading, 2=Processing, 3=Ready, 4=Failed, 5=Expired

```rust
impl AttachmentRepository {
    pub fn new(db: Arc<Database>) -> Self

    // Attachment CRUD

    pub fn delete(&self, id: &AttachmentId) -> Result<(), StorageError>

    // Queries
    pub fn list_by_status(&self, status: AttachmentStatus) -> Result<Vec<Attachment>, StorageError>

    // Thumbnail operations
    pub fn get_thumbnail(&self, attachment_id: &AttachmentId) -> Result<Option<Thumbnail>, StorageError>
    pub fn upsert_thumbnail(&self, thumbnail: &Thumbnail) -> Result<(), StorageError>
    pub fn delete_thumbnail(&self, attachment_id: &AttachmentId) -> Result<(), StorageError>
}
```

For metadata serialization:
- Use serde_json::to_string for FileMetadata -> metadata_json
- Use serde_json::from_str for metadata_json -> FileMetadata

For binary fields (encryption_key, encryption_iv, sha256 in metadata):
- Store as BLOB in SQLite
- FileMetadata.sha256 is inside JSON, keep as Vec<u8> serialized by serde

AVOID: Don't store encryption keys in JSON (keep as separate BLOB columns for potential future key rotation). Use while loop for list queries (avoid rusqlite lifetime issues).
